The big one. A subagent traced `/launch` end-to-end and confirmed the

  `getOrCreateCreator` + `createProject` when user is logged in and

  existing mock response so the landing flow still works.
- **`/home`**: uses `useProjects()`, buckets real projects into
  `JUST LAUNCHED` (createdAt DESC) / `LEGENDARY` / `RISING` /
  `UNEXPLORED`, falls back to `MOCK_*` when empty, caps each bucket

  see below.)*
- **`/project/[id]`**: reads via `useProjects()` instead of the

- **New mapper `projectsToCards()`** next to the grid: `evolution_stage`

**Requires migration 038.** See _Outstanding_ below.

### 4. Text contrast fix — `265675c`
**Bug:** the new `hq-*` components used `var(--muted)` and `var(--dim)`
as text colors, but shadcn defines `--muted` in `globals.css` as
`oklch(0.2 0.005 270)` — a near-black **background** token. `--text`
and `--dim` were never defined at all. Result: body copy, tile names,
feature section eyebrows all rendered nearly black-on-black.

**Fix:** define namespaced text tokens in `retro-game.css`:
```css
--text: #E8E8EC;        /* primary */
--text-muted: #8B7AA0;  /* secondary dim */
--text-dim: #4A4050;    /* tertiary very dim */
```
Replace `var(--muted) → var(--text-muted)` and `var(--dim) →
var(--text-dim)` across 4 files — 46 usages total. Alex flagged the
regression from a live Safari screenshot; screenshot-confirmed
readable after the fix.

## Architecture touch

### The `evolution_stage → rarity` mapping

`projects.evolution_stage` already exists in the DB (migration 033) 
as a 6-stage enum auto-computed from traction: Seed → Active →
Growing → Breakout → Legend → Myth. That maps 1:1 to the HeroCard
rarity scale:

| Stage    | Rarity    | Card stamp color        |
|----------|-----------|-------------------------|
| Seed     | common    | gray                    |
| Active   | uncommon  | neon green              |
| Growing  | rare      | neon cyan               |
| Breakout | epic      | neon orange             |
| Legend   | legendary | neon yellow (w/ glow)   |
| Myth     | myth      | neon pink+purple rainbow |

New projects start at `Seed` / `common` and show up in the
`UNEXPLORED` bucket. As traction grows they migrate up via the
DB trigger. No manual curation needed.

### Why `/api/projects/submit` keeps a mock fallback

The landing page `InteractiveDemo` posts to the same endpoint in
logged-out mode (no cookies, no session) to show prospective users
what a submission flow looks like. Killing the mock path would
break that demo. The route now branches: authed → real insert +
`persisted: true`, unauthed → mock response + `persisted: false`.
The frontend redirect works either way; the mock id just lands on
a 404 (`LOADING HERO…` then not found), which is fine for the demo.

## Outstanding — for tomorrow

### 🔴 Must do before authed launches work
**Run migration 038** in Supabase Dashboard SQL Editor. Paste this,
hit Run (idempotent, safe to re-run):

```sql
DROP POLICY IF EXISTS "Auth insert own creator" ON creators;
CREATE POLICY "Auth insert own creator"
  ON creators FOR INSERT
  WITH CHECK (auth.uid() IS NOT NULL AND auth.uid() = auth_user_id);

DROP POLICY IF EXISTS "Own update creators" ON creators;
CREATE POLICY "Own update creators"
  ON creators FOR UPDATE
  USING (auth.uid() = auth_user_id)
  WITH CHECK (auth.uid() = auth_user_id);
```

**Why:** `projects.creator_id` is `NOT NULL REFERENCES creators(id)`.
RLS already allows authed users to insert projects (migration 003),
but creators has no INSERT policy, so authed users can't create
their own creator row — and without a creator row, projects INSERT
fails the FK check. 038 closes that gap.

Without 038, authed submit returns 500 "Could not establish creator
profile". Logged-out falls through to mock.
